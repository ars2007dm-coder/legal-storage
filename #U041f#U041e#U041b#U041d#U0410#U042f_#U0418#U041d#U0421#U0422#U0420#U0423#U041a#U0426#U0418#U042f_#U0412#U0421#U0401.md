# ФСМО lite — полная инструкция: код + все платформы

Один документ от начала до конца. Идём по порядку, ничего не пропускаем.
Если что-то уже сделано раньше (например, Node.js уже стоит) — просто
переходите к следующему шагу.

---

# ЧАСТЬ A. Обновить код на компьютере

### A.1. Скачать и распаковать

1. Скачайте последний `fsmo-lite-project.zip` (тот, что в этом чате)
2. Распакуйте (правой кнопкой → «Извлечь всё» на Windows, двойной клик
   на Mac)
3. Откройте папку `fsmo-lite` в VS Code: **File → Open Folder...**

### A.2. Перенести новые файлы поверх старых

Если у вас уже был открыт этот же проект раньше — просто **замените**
все файлы новыми из архива (перетащите папки `src`, `sql` и файлы
`tailwind.config.ts`, `README_ИНСТРУКЦИЯ.md` и т.д. поверх старых,
согласитесь на замену). Файл `.env.local` **не трогайте** — он у вас
уже свой, с настоящими ключами, его в архиве нет специально.

### A.3. Проверить локально

В терминале VS Code (`` Ctrl+` `` / `` Cmd+` ``):

```
npm install
npm run dev
```

Откройте `http://localhost:3000` — должна открыться уже тёмная версия
сайта с бордовым акцентом. Если видите старую светлую — жёстко
обновите страницу (`Cmd+Shift+R` / `Ctrl+Shift+R`).

# ЧАСТЬ B. Обновить базу данных в Supabase

Все скрипты — по одному, в этом порядке. Каждый раз: Supabase →
ваш проект → **SQL Editor** → **New query** → вставить содержимое
файла → **Run**.

| № | Файл | Что делает |
|---|------|-----------|
| 1 | `sql/fsmo_lite_database_v3.sql` | Базовые таблицы избранного, RLS, поиск (если ещё не выполняли) |
| 2 | `sql/fsmo_lite_database_v4.sql` | Заявки на доступ, домашние задания |
| 3 | `sql/fsmo_lite_database_v5.sql` | 15 основных кодексов с проверенными ссылками |
| 4 | `sql/fsmo_lite_database_v5_cleanup_placeholders.sql` | Удаление тестовых видео (необязательно — можно вместо этого чистить через `/admin/videos`) |
| 5 | `sql/fsmo_lite_database_v6_more_npa.sql` | Ещё 15 НПА: законы, ФКЗ, постановления Пленума ВС |

Если какой-то из них уже выполняли раньше — можно смело запускать
повторно, они написаны так, чтобы не ломаться от повторного запуска.

**Проверка:** выполните `SELECT count(*) FROM refs;` — должно
показать 30 (если делали и v5, и v6).

# ЧАСТЬ C. Подключить SMS (Twilio)

Без этого кнопка «Войти» не будет присылать настоящий код.

### C.1. Регистрация

1. **https://www.twilio.com/try-twilio** → заполните форму → **Start
   your free trial**
2. Подтвердите почту (ссылка в письме) и телефон (SMS-код на сайте)
3. В мастере настройки выбирайте любые ответы (например "I'm a
   developer") → **Next** до конца, попадёте в Console

### C.2. Получить номер

1. Слева: **Phone Numbers → Manage → Active numbers**
2. Если номера нет — **Buy a number**, выберите любой с галочкой SMS
3. Скопируйте номер (вид `+1XXXXXXXXXX`)

### C.3. Взять ключи

1. Главная страница Console (**console.twilio.com**)
2. Блок **Account Info** → скопируйте **Account SID** и **Auth Token**
   (Auth Token скрыт — нажмите иконку глаза)

### C.4. Подтвердить свой номер (пока аккаунт Trial)

Пробный Twilio отправляет SMS только на подтверждённые номера:
**Phone Numbers → Manage → Verified Caller IDs → Add a new Caller
ID** → введите свой номер → подтвердите кодом. Чтобы пускать всех
учеников без ограничения — нужно пополнить баланс Twilio (от 20$,
дальше платите по факту).

### C.5. Подключить в Supabase

1. Supabase → ваш проект → **Authentication** (значок замка слева)
2. **Providers** → найдите **Phone** → раскройте
3. Включите **Enable Sign in with Phone**
4. **SMS Provider** → выберите **Twilio**
5. Заполните: **Twilio Account SID**, **Twilio Auth Token**, **Twilio
   Phone Number** (из шагов C.2–C.3)
6. **Save**

# ЧАСТЬ D. Письма о заявках (Resend)

1. **https://resend.com** → **Sign Up** (можно через Google)
2. Слева **API Keys** → **Create API Key** → любое имя → **Add**
3. Скопируйте ключ `re_...` сразу — второй раз не покажут

Без домена письма идут только на почту, которой регистрировались в
Resend — этого достаточно, чтобы получать уведомления себе.

# ЧАСТЬ E. ИИ-проверка домашки (Anthropic)

1. **https://console.anthropic.com** → регистрация
2. Слева **Billing** → пополните баланс (хватит 5$ на тесты)
3. Слева **API Keys** → **Create Key** → любое имя → скопируйте ключ
   `sk-ant-...` сразу

# ЧАСТЬ F. Ключи Supabase и пароль админки

### F.1. Service Role Key

Supabase → шестерёнка **Project Settings** → **API** → раздел
**Project API keys** → строка **service_role** → иконка глаза →
скопировать.

**Никому не показывайте этот ключ** — полный доступ к базе в обход
всех ограничений.

### F.2. Пароль админки

Придумайте свой пароль для входа в `/admin` вашего сайта — любой,
не слишком простой.

# ЧАСТЬ G. Собрать всё в `.env.local`

Откройте `.env.local` в VS Code, приведите к такому виду (свои
значения из частей B–F вместо `<...>`):

```
NEXT_PUBLIC_SUPABASE_URL=https://dptjwqsoisqlbaiolvmx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<был указан изначально>

SUPABASE_SERVICE_ROLE_KEY=<из части F.1>
ADMIN_PASSWORD=<из части F.2>

RESEND_API_KEY=<из части D>
ADMIN_EMAIL=<ваша почта>

ANTHROPIC_API_KEY=<из части E>
```

Сохраните (`Cmd+S`), в терминале `Ctrl+C`, затем снова `npm run dev`.

# ЧАСТЬ H. Отправить код на GitHub и в Vercel

### H.1. GitHub

```
git add .
git commit -m "Тёмная тема, SMS, ИИ-проверка, расширенная база НПА"
git push
```

### H.2. Переменные окружения в Vercel

1. **vercel.com** → проект **legal-storage** → **Settings** →
   **Environment Variables**
2. Добавьте (**Add New** для каждой) те же пять новых переменных, что
   в части G: `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PASSWORD`,
   `RESEND_API_KEY`, `ADMIN_EMAIL`, `ANTHROPIC_API_KEY` — везде
   оставляйте отмеченными все три галочки окружений
3. Вкладка **Deployments** → у верхнего деплоя `⋯` → **Redeploy**
   (обязательно — иначе новые переменные не применятся)

Если `git push` уже сам запустил новый деплой (после Части H.1) — всё
равно сделайте **Redeploy** после добавления переменных, чтобы точно
подхватились.
