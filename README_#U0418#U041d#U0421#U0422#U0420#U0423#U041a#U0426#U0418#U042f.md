# ФСМО lite — инструкция по подключению (для новичка)

Этот архив содержит весь код проекта по брифу: главную страницу, страницы
НПА / Литература / Задачи / Поиск / Избранное / Админку, авторизацию по
телефону (пока заглушка) и SQL-скрипт для базы данных.

---

## Шаг 1. Обновить базу данных Supabase

1. Откройте https://supabase.com → войдите → откройте проект **legal-storage**.
2. Слева найдите раздел **SQL Editor** → **New query**.
3. Откройте файл `sql/fsmo_lite_database_v3.sql` из этого архива, скопируйте
   весь текст и вставьте в редактор.
4. Нажмите **Run**. Скрипт безопасно выполнять даже повторно — он:
   - исправит все ссылки `http://` на `https://` в таблице `refs`;
   - создаст таблицы `profiles`, `folders`, `favorites`;
   - включит защиту данных (RLS), чтобы пользователи не видели чужие данные;
   - создаст функцию поиска `global_search`, которую использует страница `/search`.
5. Проверка: выполните `SELECT * FROM global_search('право');` — должны
   вернуться строки из разных таблиц.

## Шаг 2. Заменить файлы проекта

Скопируйте папку `src`, а также `sql/`, `package.json`, `tailwind.config.ts`,
`postcss.config.js`, `next.config.js`, `tsconfig.json` из этого архива в
корень вашего проекта, заменив старые файлы.

Если проекта ещё нет локально — склонируйте его с GitHub:
```
git clone <ссылка на ваш репозиторий ars2007dm-coder>
cd <папка проекта>
```
и уже туда скопируйте содержимое архива.

## Шаг 3. Настроить переменные окружения

В корне проекта создайте файл `.env.local` (без `.example` на конце) со
следующим содержимым (можно скопировать из `.env.local.example`):

```
NEXT_PUBLIC_SUPABASE_URL=https://dptjwqsoisqlbaiolvmx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<ваш anon key из брифа>
```

Файл `.env.local` не должен попадать в Git (обычно это уже настроено в
`.gitignore` у Next.js-проектов).

## Шаг 4. Установить зависимости и запустить локально

Убедитесь, что установлен Node.js (версия 18 или новее) — скачать можно на
https://nodejs.org (кнопка LTS).

В терминале, в папке проекта:
```
npm install
npm run dev
```
Откройте http://localhost:3000 — должна открыться новая главная страница.
Проверьте переходы: НПА, Литература, Задачи, Поиск (введите слово "право"),
кнопку "Войти" (код-заглушка: **1234**).

## Шаг 5. Залить изменения на GitHub

```
git add .
git commit -m "Реализация ФСМО lite по брифу"
git push
```

## Шаг 6. Деплой на Vercel

Если Vercel уже подключён к репозиторию (проект `legal-storage`), деплой
запустится автоматически после `git push` — зайдите в панель Vercel →
ваш проект → вкладка **Deployments** и дождитесь статуса "Ready" (1–2 минуты).

Если Vercel ещё не подключён:
1. Зайдите на https://vercel.com → **Add New → Project**.
2. Выберите ваш GitHub-репозиторий.
3. В разделе **Environment Variables** добавьте те же две переменные,
   что и в `.env.local` (шаг 3).
4. Нажмите **Deploy**.

## Часть 2 — заявки на доступ, ДЗ, ИИ-проверка, расширенная админка

Это добавлено поверх части 1. Нужно:

### 1. Выполнить sql/fsmo_lite_database_v4.sql

Так же, как v3 — Supabase → SQL Editor → New query → вставить содержимое
`sql/fsmo_lite_database_v4.sql` → Run. Добавит таблицы заявок на доступ,
домашних заданий и поле "категория" у книг.

### 2. Взять Service Role Key в Supabase

Supabase → ваш проект → значок шестерёнки **Settings** → **API** →
раздел **Project API keys** → скопируйте **service_role** (НЕ anon —
это секретный ключ с полным доступом к базе, никому не показывайте
и не публикуйте).

### 3. Завести Resend (для писем о заявках) — необязательно, но рекомендуется

1. **resend.com** → зарегистрируйтесь
2. В личном кабинете слева **API Keys** → **Create API Key** → скопируйте
3. Без домена можно отправлять письма только на свою почту (ту, на
   которую регистрировались) — этого достаточно для уведомлений себе

### 4. Завести Anthropic API-ключ (для ИИ-проверки ДЗ)

1. **console.anthropic.com** → зарегистрируйтесь
2. Слева **API Keys** → **Create Key** → скопируйте
3. Там же нужно пополнить баланс (раздел **Billing**) — это платный
   API, отдельно от подписки Claude.ai; для проверки десятков ответов
   в месяц расходы обычно небольшие (доллары, не десятки долларов)

### 5. Дополнить .env.local

Допишите в файл `.env.local` (не `.example`) новые строки со своими
значениями:
```
SUPABASE_SERVICE_ROLE_KEY=<service_role ключ из шага 2>
ADMIN_PASSWORD=<придумайте свой пароль для входа в /admin>
RESEND_API_KEY=<ключ из шага 3, можно оставить пустым>
ADMIN_EMAIL=<ваша почта, куда слать уведомления>
ANTHROPIC_API_KEY=<ключ из шага 4>
```
Сохраните, перезапустите `npm run dev` (`Ctrl+C`, затем `npm run dev`
заново) — так же, как при первой настройке.

Те же переменные добавьте в Vercel: **Settings → Environment Variables**
(шесть пар — старые две из части 1 плюс пять новых), затем
**Redeploy** последнего деплоя.

### 6. Проверка

- `/join` — заявка на доступ (укажите тестовый номер)
- `/admin/requests` (после входа в `/admin` с вашим ADMIN_PASSWORD) —
  видна заявка, кнопка «Одобрить» выдаёт код
- `/verify` — ввести тот же номер и код → должна появиться вкладка
  «ДЗ» в шапке сайта
- `/admin/homework` — добавить тестовое задание с любым эталонным ответом
- `/homework` — открыть задание, ответить, отправить на проверку —
  должен прийти развёрнутый разбор от ИИ с оценкой
- `/admin/add` — добавить тестовый НПА/книгу/задачу, проверить, что
  появились на соответствующих страницах

### Важные оговорки

- **Это не банковская защита.** Доступ к ДЗ и админке — это удобный
  барьер для случайных посетителей, а не криптографически надёжная
  система. Технически подкованный человек с ключом Supabase (он
  публичный, лежит в коде сайта) может обойти проверку через прямые
  запросы к API. Модельные ответы к ДЗ я спрятал отдельно, чтобы хотя
  бы их не было видно напрямую — но сама возможность существования ДЗ
  и структура сайта не секретны.
- **Общая кнопка «Войти» в шапке (для избранного) пока не работает
  по-настоящему** — она осталась в виде тестовой заглушки (код 1234,
  ничего не создаёт по-настоящему), а вот `/favorites` уже ждёт
  реальную сессию Supabase Auth. Из-за этого раздел «Избранное» сейчас
  всегда будет писать «Войдите...», даже после ввода 1234. Это не
  связано с новой системой доступа к ДЗ (она отдельная, через /join и
  /verify) — просто не завершённый ранее кусок. Если нужно — скажите,
  доведу его тоже (обычно это email-ссылка для входа через Supabase
  Auth, аналогично их magic link).
- Если увидите в проекте файл `src/middleware.ts.bak` — переименуйте
  обратно в `middleware.ts` (уберите `.bak`): он нужен, чтобы сессии
  Supabase Auth не "слетали" между запросами. Раньше его пришлось
  временно отключить при отладке `.env.local` — теперь можно включить
  обратно, ошибка была не в нём.

## Часть 3 — реальные ссылки на кодексы, удаление заглушек, видео в админке

### 1. Выполнить sql/fsmo_lite_database_v5.sql

Supabase → SQL Editor → New query → вставить содержимое
`sql/fsmo_lite_database_v5.sql` → Run. Это добавит/исправит 15
основных кодексов РФ (Конституция, ГК, УК, УПК, КоАП, НК, ТК, СК, ЗК,
ГПК, АПК, ЖК) с проверенными ссылками на consultant.ru — если запись
с такой аббревиатурой уже была (даже с неправильной ссылкой) — она
обновится; если не было — добавится.

Если увидите ошибку про `refs_abbr_unique` (например, если у вас уже
есть две разные записи с одинаковой аббревиатурой) — пришлите мне
текст ошибки, поправим точечно.

### 2. Проверить тестовые видео

Откройте `sql/fsmo_lite_database_v5_cleanup_placeholders.sql` —
сначала выполните первый `SELECT`, посмотрите, что нашлось (например,
"Профессор Иванов"). Если это точно заглушки — раскомментируйте
`DELETE` в том же файле и выполните ещё раз.

### 3. Управление видео теперь в админке

`/admin/videos` — можно добавлять/удалять записи о видеоразборах без
захода в Supabase. Если после шага 2 захотите добавить настоящие
видео — делайте это здесь.

### Что я НЕ стал делать — и почему

Не стал скачивать и заливать на сайт материалы из присланной папки на
Яндекс.Диске (доктрина/практика). Это, по всей видимости, чей-то

## Часть 4 — расширенная база НПА (кодексы, законы, ФКЗ, ППВС)

### Выполнить sql/fsmo_lite_database_v6_more_npa.sql

Supabase → SQL Editor → New query → вставить содержимое
`sql/fsmo_lite_database_v6_more_npa.sql` → Run.

Добавляет ещё 15 проверенных документов (итого станет 30 в таблице
`refs`, если до этого выполнялся v5):

- **Ещё кодексы:** Бюджетный, Градостроительный, КАС РФ
- **Федеральные законы:** о персональных данных, о защите прав
  потребителей, об ООО, об АО, о банкротстве, о полиции, о прокуратуре
- **ФКЗ:** о Конституционном Суде РФ, о судебной системе РФ
- **Постановления Пленума ВС РФ (ППВС):** №25 (о части первой ГК РФ),
  №58 (о назначении наказания), №33 (о компенсации морального вреда)

Все ссылки я лично проверил через поиск на КонсультантПлюс — номера
`cons_doc_LAW_XXXXX` я не придумывал, а нашёл в реальных статьях
кодексов на их сайте.

Скрипт устроен так же, как v5: если документ с такой аббревиатурой уже
есть в базе — обновит ему ссылку, если нет — добавит новый. Можно
спокойно выполнять повторно.

**Если нужно ещё больше** (постановления Правительства, приказы
министерств, региональные акты, ППВС по другим темам) — напишите,
какая тема или отрасль права в приоритете, и я подберу и проверю ещё
один пакет так же вручную. Без конкретной темы "максимально возможное"
количество легко доходит до сотен документов, но тогда я не смогу
вручную проверить каждую ссылку — лучше пакетами по 15-20 с проверкой,
чем один раз вставить непроверенный список.

## Если что-то не работает

- Белый экран / ошибка "supabaseUrl is required" → не создан `.env.local`
  или не перезапущен `npm run dev` после его создания.
- Ссылки на НПА не открываются → возможно, SQL-скрипт (шаг 1) не был выполнен.
- Страница `/favorites` просит войти, хотя вы вошли → это ожидаемо для
  заглушки авторизации: она не создаёт настоящую сессию в Supabase Auth,
  только "проходит" модалку. Реальные личные кабинеты заработают после
  подключения Twilio (см. выше).
